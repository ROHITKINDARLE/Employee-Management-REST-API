# Employee Management REST API

A beginner-friendly REST API for creating, viewing, searching, updating, and deleting employee records. It uses Express.js for HTTP routes and MongoDB with Mongoose for persistence.

## Technology stack

- Node.js and CommonJS
- Express.js
- MongoDB and Mongoose
- dotenv for environment configuration
- express-validator for request validation
- nodemon for development
- Postman for manual API testing

## Installation and startup

1. Install the project dependencies:

   ```bash
   npm install
   ```

2. Ensure the MongoDB service is running. For a local installation, start the MongoDB service using the method appropriate for your operating system. The default URI points to `127.0.0.1:27017`.

3. Configure the environment variables in `.env`:

   ```env
   PORT=5000
   MONGO_URI=mongodb://127.0.0.1:27017/employee_management
   ```

   Replace `MONGO_URI` if your MongoDB server uses a different address. Do not commit `.env`; it is excluded by `.gitignore`.

4. Start the server:

   ```bash
   # Development (restarts on file changes)
   npm run dev

   # Normal startup
   npm start
   ```

The application connects to MongoDB before it starts listening for requests. A successful startup logs the MongoDB host and server port. If the connection fails, the application reports the startup error and exits.

## Employee fields and validation

Each employee document has these seven application fields:

| Field | Type | Rules |
|---|---|---|
| `fullName` | String | Required, trimmed, non-empty |
| `email` | String | Required, valid email, trimmed, lowercase, unique |
| `phoneNumber` | String | Required; accepts an international number with `+` or an Indian 10-digit number, optionally prefixed by `0` |
| `department` | String | Required, trimmed, non-empty |
| `designation` | String | Required, trimmed, non-empty |
| `salary` | Number | Required, zero or greater |
| `joiningDate` | Date | Required, valid ISO 8601 date |

Request-level checks use express-validator and the Mongoose model repeats the relevant validations. Email uniqueness is enforced by a MongoDB unique index. An existing email returns `409 Conflict`. Create and update requests must include all seven fields and must not include extra fields.

## API endpoints

Base URL: `http://localhost:5000`

For JSON requests, set the `Content-Type` header to `application/json`.

### 1. Create an employee

`POST /api/employees` — returns `201 Created`.

Request body:

```json
{
  "fullName": "Rohit Sharma",
  "email": "rohit.sharma@example.com",
  "phoneNumber": "+919876543210",
  "department": "IT",
  "designation": "Software Engineer",
  "salary": 75000,
  "joiningDate": "2024-01-15"
}
```

Success response (`201`):

```json
{
  "success": true,
  "message": "Employee created successfully",
  "data": {
    "_id": "6650c0f1a9e3b2d12a345678",
    "fullName": "Rohit Sharma",
    "email": "rohit.sharma@example.com",
    "phoneNumber": "+919876543210",
    "department": "IT",
    "designation": "Software Engineer",
    "salary": 75000,
    "joiningDate": "2024-01-15T00:00:00.000Z",
    "__v": 0
  }
}
```

The `_id` and `__v` properties are generated by Mongoose.

### 2. Get all employees

`GET /api/employees` — returns `200 OK`.

Optional query parameters:

- `search`: partial, case-insensitive match against `fullName`
- `department`: exact department match
- `page`: positive integer; defaults to `1`
- `limit`: positive integer; defaults to `10`

Examples:

```text
GET /api/employees
GET /api/employees?search=rohit
GET /api/employees?department=IT
GET /api/employees?page=1&limit=5
GET /api/employees?search=rohit&department=IT&page=1&limit=5
```

Success response (`200`):

```json
{
  "success": true,
  "message": "Employees retrieved successfully",
  "data": {
    "employees": [],
    "pagination": {
      "currentPage": 1,
      "pageSize": 10,
      "totalRecords": 0,
      "totalPages": 0
    }
  }
}
```

Search and department filtering are combined before pagination and total-record counting. Invalid page or limit values return `400 Bad Request`.

### 3. Get an employee by ID

`GET /api/employees/:id` — returns `200 OK` when found.

Example: `GET /api/employees/6650c0f1a9e3b2d12a345678`

Success response (`200`):

```json
{
  "success": true,
  "message": "Employee retrieved successfully",
  "data": {
    "_id": "6650c0f1a9e3b2d12a345678",
    "fullName": "Rohit Sharma",
    "email": "rohit.sharma@example.com",
    "phoneNumber": "+919876543210",
    "department": "IT",
    "designation": "Software Engineer",
    "salary": 75000,
    "joiningDate": "2024-01-15T00:00:00.000Z",
    "__v": 0
  }
}
```

Malformed IDs return `400`; valid IDs for missing records return `404`.

### 4. Update an employee

`PUT /api/employees/:id` — returns `200 OK`.

Send the complete employee object (all seven fields), using the same JSON shape as the create request. Values and email uniqueness are revalidated.

Success response (`200`):

```json
{
  "success": true,
  "message": "Employee updated successfully",
  "data": {
    "_id": "6650c0f1a9e3b2d12a345678",
    "fullName": "Rohit Sharma",
    "email": "rohit.sharma@example.com",
    "phoneNumber": "+919876543210",
    "department": "IT",
    "designation": "Senior Software Engineer",
    "salary": 90000,
    "joiningDate": "2024-01-15T00:00:00.000Z",
    "__v": 0
  }
}
```

### 5. Delete an employee

`DELETE /api/employees/:id` — returns `200 OK`.

Success response (`200`):

```json
{
  "success": true,
  "message": "Employee deleted successfully",
  "data": {}
}
```

## Error responses

Errors use a JSON response with `success: false` and a meaningful `message`. Request validation may also include an `errors` array. Common statuses are:

| Status | Meaning |
|---|---|
| `400` | Invalid or incomplete input, invalid pagination, or malformed employee ID |
| `404` | Employee or route not found |
| `409` | Duplicate email address |
| `500` | Unexpected server error |

Example:

```json
{
  "success": false,
  "message": "Email already exists"
}
```

Unexpected server responses do not expose database details or stack traces. Detailed errors are logged by the server.

## Postman testing guide

1. Start MongoDB and run `npm run dev`.
2. In Postman, create a request to `http://localhost:5000`.
3. For POST and PUT requests, choose **Body → raw → JSON** and set `Content-Type: application/json`.
4. Use the successful create response's `_id` in the get, update, and delete requests.

### Checklist

| # | Request | Expected result |
|---|---|---|
| 1 | `POST /api/employees` with the valid sample body above | `201`; employee returned |
| 2 | `GET /api/employees` | `200`; employee list and pagination metadata |
| 3 | `GET /api/employees/:id` with the created ID | `200`; employee returned |
| 4 | `PUT /api/employees/:id` with all seven valid fields and a changed designation or salary | `200`; updated employee returned |
| 5 | `DELETE /api/employees/:id` with the created ID | `200`; deletion message |
| 6 | `GET /api/employees?search=rohit` | `200`; partial case-insensitive name results |
| 7 | `GET /api/employees?department=IT` | `200`; only matching department results |
| 8 | `GET /api/employees?page=1&limit=5` | `200`; at most five results with pagination metadata |
| 9 | `GET /api/employees?search=rohit&department=IT&page=1&limit=5` | `200`; combined filters and pagination |
| 10 | `POST /api/employees` with `"email": "not-an-email"` | `400`; invalid email message |
| 11 | `POST /api/employees` with `"phoneNumber": "123"` | `400`; invalid phone message |
| 12 | `POST /api/employees` with an email already stored | `409`; duplicate email message |
| 13 | `POST /api/employees` omitting a required field, such as `fullName` | `400`; required-field message |
| 14 | `POST /api/employees` with `"salary": -1` | `400`; salary validation message |
| 15 | `POST /api/employees` with `"joiningDate": "not-a-date"` | `400`; invalid-date message |
| 16 | `GET /api/employees/not-an-object-id` | `400`; invalid employee ID |
| 17 | `GET /api/employees/6650c0f1a9e3b2d12a345678` when that ID is absent | `404`; employee not found |
| 18 | `PUT /api/employees/:id` with invalid field data or a missing required field | `400`; validation message |
| 19 | `DELETE /api/employees/6650c0f1a9e3b2d12a345678` when that ID is absent | `404`; employee not found |
| 20 | `GET /api/unknown` | `404`; route not found |

For test 18, start with the successful create payload and change `salary` to a negative number or set `fullName` to an empty string. For tests 17 and 19, use a well-formed 24-character hexadecimal ObjectId that is not present in your database.

## MongoDB connection verification

On startup, check the terminal for `MongoDB connected: 127.0.0.1` (or your configured host) followed by the server listening message. If startup reports a database connection error, verify the MongoDB service is running and `MONGO_URI` is correct. The API does not begin listening until the database connection succeeds.

## Manual verification

Database-backed API requests require an available MongoDB instance and should be executed in Postman using the checklist above. This project does not include automated integration tests.
